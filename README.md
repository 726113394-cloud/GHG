# 中文

## 一、一局的完整流程

### 0. 排队开局（`/ghg join`）

不想每次都喊管理员开局，就用队列。玩家 `/ghg join` 进队，屏幕上方一条蓝色 BossBar 实时显示
`排队中 2/4 · 78 秒后取消`：

- **凑够 `min-players`（默认 2 人）就自动进入倒计时**（默认 15 秒），条变绿，到点直接开局
- 倒计时里有人跑了、人数又不够，就**退回凑人阶段继续等**，不会把半局人拉进猎场
- 凑人阶段最长等 `wait-seconds`（默认 90 秒），到点还是不够就**取消队列**并广播
- 队列期间 `/ghg leave` 只退队，不会误报「你不在对局中」；掉线的人会被静默移出
- **对局已经开始了**：`/ghg join` 会明确告诉你「已开局」，并提示用 `/ghg spectate` 进观战席
- **队列不收钱**：入场费与职业券照旧在真正开局时收，所以「排队 → 取消 → 再排」不会来回退钱
- 管理员用 `/ghga hunter start` 手动开了一局时，队列自动作废，不会在下一拍又把第二局拉起来

母体默认还是 **AI**（`hunter.queue.mother: AI`），队列里只排逃生者。想让真人当母体就把它设成
`PLAYER`——那时**从队列里随机抽一人当母体**，其余人当逃生者。谁当母体**不看入队顺序**，
所以进队时没有人能保证自己这局是猎人。

### 1. 准备阶段（默认 25 秒）

- 人类**可以自由移动**，可以踩点、可以看地形
- **法阵此刻无法破除**（站上去也不涨进度）
- **母体定身不能动**，玩家母体在这里选种类；逃生者在这里选**职业**（自动弹菜单，也能 `/ghg role`）
- **道具箱已经在场上了，可以敲开搜刮物资** —— 准备阶段就是用来抢位置、抢物资、定职业的
- **道具在准备阶段一律锁着**：除了下面那块「选择面板」，技能道具、消耗品、食物都用不了，开打才解锁
- **饱食度不掉**：这段时间每秒把饱食度与饱和度顶满，开打那一刻才按 `start-saturation` 压回去
- **选择面板（钟表）**：每人手里一块，**左键或右键**都能打开菜单（逃生者＝职业菜单，玩家母体＝母体种类菜单），
  关掉 UI 之后不用再敲命令；它不能丢，**开打时自动收走**
- 最后 5 秒锁定母体种类（`kind-lock-seconds`），同时放居中倒计时

### 2. 猎杀阶段

母体解定身开始追。逃生者**按住 Shift** 站在任意完好的法阵格上蓄力 ——
**每座法阵有自己的进度条**。实际涨速 = 基准 **1.8%/秒** × 0.9 × 这座阵上**前 2 名**蓄力者的
职业权重之和：单人普通职业 **1.62%/秒**（约 **62 秒**推满一座）、工程师 **2.03%/秒**（约 49 秒），
**两个人一起推就是两个人的权重相加**（约 31 秒）。第 3 个人起不起算，会被提示「这座阵已经满了」。
母体进这座阵 **6 格**内开始守机（**−1.5%/秒**）：普通职业被守时净 **+0.12%/秒**，**只是变慢、不再倒退**
（想把「倒退」调回来就把 `decay-per-second` 提到 2.0 以上）。
单座阵推进到 **20%** 会**瘫痪 1 分钟**：这段时间既不能继续推，母体也不能加固它。
有人蓄力时这座阵每 **0.5 秒**响一记「哒」（`charge-tick-ticks`），音高随进度上抬。

**开打前 5 秒开始挂悬念**：副标题是「母体：？？？ · 种类已锁定」；
**开打瞬间才揭晓**真实种类与技能（聊天栏 + 开场字幕）。

### 3. 撤离阶段

进度推满 **100%** 时**所有法阵同时破除**，系统再从这些刚破的阵里**随机挑一座**当撤离点，
并广播 + 响一声。按住 **Shift** 在撤离点待满 `escape.hold-seconds`（4 秒）撤离成功。
同时**终局倒计时**开始（`endgame.seconds`，默认 90 秒），走不完就一起被埋。

> 撤离点开局不存在、也不发光；而且**不会是最后破除的那一座**——按法阵的破除顺序，
> 那座就是最后一次蓄力时站着的地方，否则人一推满就能原地走人。

**一个人走出去，整局就结束**：撤离读条满的瞬间对局收尾，结算时还活着、没被淘汰的人
一起算撤离成功——不需要四个人去同一个点排队。地窖同理。

### 4. 独狼地窖

只剩 **1 名**逃生者时，地图上会开一个**地窖**（坐标会广播），按住 Shift 独自撤离。
**地窖点位也是某座法阵（随机一座）**，不额外造点。
不然 4 人死到剩 1 个，那个人还要推满整条进度再走同一个撤离点，等于没救。

**失败**：全部逃生者被击倒。**时间到不算输也不算赢——判平局**（只作为兜底，见第十二节）。

## 二、交互全部用 Shift（互通服基岩版也能玩）

Java 版和基岩版的操作差异就卡在左右键上，所以 GHG 的关键动作一律改成**潜行键**：

| 动作 | 操作 |
|---|---|
| 破法阵 | 站在法阵格里 **按住 Shift** |
| 救援倒地队友 / 拆阵救人 | 蹲在旁边 **按住 Shift**，连续待满数秒 |
| 治疗受伤队友 | 蹲在旁边 **按住 Shift**（8 秒） |
| 自愈（受伤） | 自己蹲下 **按住 Shift**（20 秒，且饱食度 ≥ 8） |
| 撤离 | 站在撤离点 **按住 Shift** 待满 4 秒 |
| 母体抱起倒地者 | 贴到 2.5 格内 **按住 Shift** 2 秒（AI 母体自动抱） |
| 从母体手里挣脱 | 被抱着时 **按住 Shift** 攒满 8 秒 |
| 母体砍击 | **左键**（必须手持「母体的战斧」） |
| 母体放技能 | **右键**（必须手持对应技能道具） |
| 母体加固法阵 | 玩家母体**左键连打碎 16 次**法阵格上的粉红色染色玻璃（玻璃一碰就碎，打满 16 次该阵加固；加固后有 60 秒冷却；AI 母体不做这个动作） |
| 工程师架栅栏 | **右键**（栅栏工具） |
| 用道具 | **右键**（破阵石要在法阵上、医疗包要受伤时）；**准备阶段全部禁用**。**左键不会触发任何道具**——敲箱子时多按的那一下不会把珍珠/控魂术/药水用掉 |
| 重选职业 / 母体种类 | 准备阶段手里那块**钟表（选择面板）**：**左键或右键**都能打开对应菜单 |

## 三、规则细节

**每座法阵一条自己的进度。** 站哪座推哪座，涨满 100% 那座阵就破除；**全部破除之后**撤离点才开。
「推哪座」于是重新变成一道取舍题：分散推能分摊风险，集中推能先拿下一座，
而单座阵推到 **20%** 时那 1 分钟瘫痪就是母体最该抓的窗口。

- **法阵数量**：默认 **4 座**（`altar.count`，1–8；填 0 = 随人数 `ceil(人数/2)`，上限 `altar.max`）
- **涨速**：单座阵的实际涨速 = `progress-per-second × 0.9 × 这座阵上蓄力者的职业权重之和`
  （**最多 2 人**，`altar.max-chargers`）。基准 **1.8** → 单人普通职业 **1.62%/秒**（推满约 62 秒）、
  工程师 1.25 → **2.03%/秒**（约 49 秒）；**两个人一起推就是上面两倍**（约 31 秒）。
  第 3 个人起**不起算**，会收到「这座阵已经满了」的提示。破阵石的加速乘在这个结果上（×2）。
  不同阵之间互不影响。`group-bonus` 键保留但已废弃
- **蓄力滴答声**：有人按住 Shift 推阵时，这座阵每 **0.5 秒**响一记「哒」（`charge-tick-ticks`，
  0 = 关），**音高随进度上抬**——离破除越近，节奏听起来越急。加固 / 瘫痪中不响
- **守机**：母体进入某座阵的 `decay-radius`（6 格）内，**那一座**的进度按 `decay-per-second`
  （1.5%/秒）回落。**注意：涨速改到 1.8 之后，普通职业被守时是 +0.12%/秒（只是变慢）**，
  不再倒退；想恢复「被守时倒退」就把 `decay-per-second` 提到 2.0 以上（最低夹在 0）
- **破阵石加速期间不瘫痪**：被破阵石加速的那 **20 秒**里，这座阵**不会**触发瘫痪；
  **加速一结束立刻补触发**（该瘫的一次都不会少）。所以石头既是加速，也是「买 20 秒干净窗口」。
  加速中这条阵的进度条会显示 `⚡加速 ×2（还剩 Ns）`，一眼能看出 buff 还在
- **瘫痪**：单座阵的进度**第一次**跨过 `paralyze.at`（默认 20%）时，这座阵停 `paralyze.seconds`
  （默认 60 秒）：站上去不涨、破阵石无效、**母体也不能加固它**；地砖变**灰色玻璃**一眼可辨。
  每座阵只触发一次，到点自动恢复并铺回粉色玻璃
- **加固**：**玩家母体**连续打碎法阵格上的**粉红色染色玻璃**满 **16 次**（`harden-hits`，中断超过 10 秒重新数）→ 那格变成**哭泣的黑曜石**，该阵**加固 50 秒**；之后 **60 秒冷却**（`harden-cooldown-seconds`）内打哪座阵都不计数
  （`harden-seconds`），期间人类站上去不涨、破阵石也无效；到期自动铺回红石块。
  AI 母体不做这个动作——它只管砍人、放技能、守机，加固是真人母体独有的压迫手段
- **撤离点**：进度满后才**随机挑一座刚破的法阵**当撤离点（排除最后破除的那座），
  中途离开进度会回落，给母体留最后翻盘窗口
- **击倒**：母体打中两次 → 原地**趴下**（爬行姿态）、无法移动、持续发光
- **被打中不减速**：命中瞬间给 **速度Ⅱ 2 秒**（挣脱），结束接 **缓慢Ⅰ 1.5 秒**（力竭）
  ——这是逃生者「换时间」的手段；禁疾跑 + 母体速度下，没有它追逐会变成必死
- **母体后摇**：砍中后母体**原地缓慢Ⅳ 2 秒**（不追不砍不放技能），且**斧头立刻消失、
  3 秒后回到手上**。回来时**只回斧头**——技能道具要等技能冷却走完才补（不会出现「手上有道具但点不动」）
- **受伤状态**：挨过一次但还没倒就是**受伤**——会**流血**（暗红粒子），可以治回健康。
  再挨一次才倒地。被救起来的人是**受伤**而不是满血，所以治疗这条线才有意义
- **治疗**：队友蹲在旁边按住 Shift 治（**8 秒**）；自己蹲着是自愈（**20 秒**，且**饱食度 ≥ 8**）。
  中断后进度会回退，跟救援一样是「有风险的行动」
- **倒地自愈**：没人处理 **15 秒**后自己爬回**受伤**状态（`recover-seconds`，0 = 关闭）
- **法阵献祭**（默认开启）：被击倒后母体可以**抱起**你，钉到任意未完成的法阵上——**该法阵随即失效**
  （站上去不涨、也破不了），同时开始倒计时：第一次 **60 秒**、第二次 **30 秒**、
  第三次 **5 秒后爆炸放飞**。AI 母体钉完会在椅子边**守 10 秒**。
  队友按住 Shift **4 秒**拆阵能把人救下来，法阵随之恢复；被抱时按住 Shift **8 秒**可自己挣脱。
  **上椅计时取代了倒地放血**——`bleedout-seconds` 只在 `chair.enabled: false` 时才生效
- **救援是读条**：同伴蹲在旁边按住 Shift，连续待满 **3 秒**才救起；松手、走开、自己也倒下都会中断
- **救人保护**：被救下后 **3 秒**内母体砍不动
- **每人每局最多被救 1 次**（`rescue-limit`）
- **被救的和救人的都会发光一段时间**（默认 4 秒）

> 发光时长别调长。MC 的发光是**全服可见**，做不到「只对队友可见」，
> 持续发光会让「击倒」直接等于「淘汰」，还会顺着光找到救援者。

## 四、关键数值总表

逃生者侧的所有时间与距离（对应 `hunter.*` 配置）：

| 事件 | 数值 |
|---|---|
| 击倒条件 | 被母体打中 **2 次**（第 1 次是「受伤」） |
| 母体命中人类 | **命中瞬间不减速**：先给逃生者 **速度Ⅱ 2 秒**，结束接 **缓慢Ⅰ 1.5 秒** |
| 母体后摇 | 砍中后母体**原地缓慢Ⅳ 2 秒**，且**斧头立刻消失、3 秒后回到手上**（技能道具不跟着回，等 CD） |
| 击倒发光 | **4 秒** |
| 倒地姿态 | 击倒后**趴下**（`Pose.SWIMMING`，用 `setPose(pose, fixed=true)` 锁住 + 每 tick 重申）；**坐标锁定**（自己走不了，等救援或 15 秒自愈） |

## 五、法阵献祭：钉在法阵上

倒地之后不再是「躺着等放血」，而是被母体**抱到法阵上钉住**——**人一钉上去，这座法阵立刻失效**：
站上去不涨进度、破阵石也无效；被救走后恢复可用。这是 GHG 里唯一的淘汰途径
（`hunter.chair.enabled: false` 才退回老的放血规则）。

```
击倒(趴下) → 母体抱起/骑乘 → 走到任意未完成的法阵 → 钉上：法阵失效 + 开始倒计时
                                        ↘ 队友按住 Shift 拆阵 4 秒 → 救下·受伤状态·法阵恢复
                                         ↘ 倒计时归零 → 升天·转旁观
```

**抱起**：玩家母体**按住 Shift 贴在倒地者 2.5 格内 2 秒**就抱起来（不新增键位，和破阵/救援/撤离一样都是 Shift）；
AI 母体看到 24 格内的倒地者会主动走过去抱。抱起后优先**骑乘**（真的「抱」在身上），
骑乘挂不上就退回每 tick 牵引跟随。抱着人时移速 ×0.75（`carry-speed`）。

**钉上**：走到任意**未充能**的法阵 2.5 格内自动钉上。上椅次数决定倒计时：第一次 60 秒、
第二次 30 秒、第三次 5 秒后**爆炸放飞**。

**为什么用法阵当椅子**：法阵本来就是这张图上唯一的目标物。把人和目标绑在一起，
母体守人就等于守阵、逃生者救人就是抢回一座阵——一个动作同时推进两条线，不用再造一套椅子点位。

**救援与兜底**：队友在法阵旁按住 Shift `rescue-seconds`（4 秒）拆阵救人，救下来是**受伤**状态。
**没人处理就自己爬起来**：倒地后 `recover-seconds`（默认 15 秒）内母体不来抱走/钉阵，人会自己爬回
**受伤**状态——攻击链是 健康 → 受伤 → 倒地，倒地时流血已结算，所以爬起来是带伤而不是满血。

**自救已移除**：原来「按住 Shift 消耗第二次机会自己站起来」那套整套删掉了，倒地只能等人救或等 15 秒自愈。
新道具**救赎护符**（紫水晶碎片）改成「缩短救人读条」：右键后 15 秒内救人读条速度 ×3——
但它**不能远程救人**，仍然要走到队友/法阵旁按住 Shift。

| 配置 | 默认 |
|---|---|
| `hunter.chair.enabled` | true（false = 退回放血规则） |
| `hunter.chair.first-seconds` / `second-seconds` | 60 / 30 |
| `hunter.chair.third-seconds` | 5（第三次上椅的倒计时，到点爆炸） |
| `hunter.chair.rescue-seconds` | 4 |

| `hunter.chair.ai-camp-seconds` | 10 |

## 六、逃生者职业

每局给每个逃生者随机一个职业，职业决定「主动技能 + 被动倾向」。技能道具直接引用常驻道具，
**不可叠加**（背包里只留一件），而且**只有在用掉之后才开始计时补发**。
**职业技能道具不会从道具箱里开出来**——它们只由职业补发，避免和箱子叠成两件。

准备阶段会自动弹出**职业选择菜单**（也能用 `/ghg role` 打开）：换职业按**差价**补/退职业券，

不用再翻文档才知道自己选了什么。

`Mob` 或 `Player`，所以调试时能真人验证手感。

| 目标优先级 | 正在破阵的人权值 **−12 格**（优先抓），当前目标额外带黏性（不来回横跳） |
| **跳跃提升（仅 AI）** | **跳跃提升 Ⅲ ≈ 跳 3 格**，每 3 秒续一次；**玩家母体不给** |
| **卡住自动脱困** | AI 母体位置一直在 **4 格**范围内且持续 **6 秒** → 判定卡住，**只在原地 2~3 格内找一个站得住的落脚点挤出去**（旁边一格 / 上一级台阶）。**绝不瞬移到逃生者身边**；找不到就只清一次路径 |
| 寻路 | Pathfinder 返回值判定 + 目标点抬到落脚面 + 中间点重试 + 撞栅栏（3 下塌），三层兜底 |

> 技能冷却可以被 `hunter.mother.skill-cooldown` 全局覆盖；减速类技能的默认值在
> `hunter.mother.skill-slow-*`（缚网用它），炼金者另有自己的 `potion.slow-*`。

怎么定种类：

- `hunter.mother.kind: RANDOM`（默认）→ **AI 每局从 `enabled-kinds` 里随机抽一个**
- `hunter.mother.kind: WALKER` → 固定成这一种
- **玩家母体**在准备阶段用 `/ghga hunter kind <种类>` 自己选；AI 母体也能用这条命令，
  会重新生成对应外观的实体
- 种类菜单（`/ghg kind`，准备阶段自动弹）每个条目写着：**这个种类是干什么的**、
  **技能的逐行效果**、**冷却**、**本局门票**、以及所有母体共用的**透视被动**
- `hunter.mother.type: AUTO` → 用种类自带的默认外观（僵尸 / 尸壳 / 骷髅 / 女巫 / 末影人 / 流浪者 / 蜘蛛）；
  填具体实体名则**只换皮，技能仍由种类决定**

AI 母体在索敌范围内自动放技能；玩家母体**拿着「技能道具」右键**放（开局与换种类时自动发到快捷栏，
材质与名字随种类变，**不可丢弃**）。冷却共用 `skills.<技能>.cooldown`。
**测试局的 `hunter.test.ignore-skill-cooldown` 只对玩家母体生效**——AI 母体在任何模式下都吃冷却，
否则它每秒 tick 一次，就成了「无限放技能」。

**AI 的决策顺序**（`MotherBrain`）：正在按 Shift 破阵的人优先 → 其次看距离（带黏性）→
目标跑出感知范围后先去**最后已知位置**找 `search-seconds` 秒 → 还是没人就按守机顺序蹲点
（有人正在推的阵 → 最近的未加固阵 → 撤离点）。

**决策频率**：追击单独跑 **10 刻一拍**（`tickMotherChase`），只有砍人 / 放技能 / 椅子逻辑留在 1 秒那套里。
原来全程 1 秒一拍，目标跑出去半秒她才开始挪，看起来就是在发呆。

**移动只能有一个控制者**：`setTarget` 与 Paper 的 Pathfinder 同时开就会互相抢、直抽搐。所以：
平时**用 Pathfinder 追「预判点」**（`chase.pathfinder`，目标 0.5 秒后的位置 → 自然切角、会拐墙角），
寻路失败或距离很近时才退回原版 `setTarget`；**绕后 / 假动作**和**搜索 / 巡逻**也走 Pathfinder。
两条路线都兜异常，没有 Paper 的服务端会一路退化成「朝目标给速度 + 跳一下」。

**卡住判定从 6 秒收紧到 3 秒**（`stuck-seconds`）：6 秒足够玩家跑掉半张图，看起来像站桩。
真卡住时仍是**原地挤 2~3 格**，不会瞬移到逃生者身边。

**生成与看门狗**：开局会在离锚点 `spawn-distance` 格的**八个方向**里找一个站得住、且与锚点高差不超过 6 格的落点
（原来只试 +X 一个方向，那一列是墙或屋顶时母体会被顶到屋顶上）；生成前先 `load()` 目标区块
（NoSpawnChunks 类插件会让远处区块没加载，直接把 `spawnEntity` 打回），生成后核对有效性并把
实体标成 `persistent`。母体如果被清理插件清掉、掉虚空或被 OP 杀掉，**1 秒内会自动补刷一只**
（3 秒节流，控制台记一次坐标）。

## 八、道具与物资

**道具只从道具箱出**，不往地上丢。箱子是**西瓜**（`chest.material`），敲 **5 下**破，
开出 **2 件**，都是从下面的随机池里抽（口粮已经**不再保底**——饱食度压力要靠自己攒吃的）。

逃生者随机池（`ItemIds.survivorPool`，职业技能道具**不进箱子**）：

| 道具 | 材质 | 效果 |
|---|---|---|
| **应急口粮** | 面包 | 按住右键**真进食**，一份一口（`bites: 1`），每口回 6 点饱食度 + 4 饱和度。**可以叠成一摞**，**不再保底必出** |
| **医疗包** | 蜂蜜瓶 | 右键**立刻治好受伤**（`medkit.instant`） |
| **破阵石** | 燧石 | 站在法阵上右键：脚下这座阵的破解速度 **×2** 持续 **20 秒**；用掉即消耗，**CD 30 秒**（加固 / 瘫痪中无效） |
| **控魂术** | 时钟 | **定身母体 4 秒**（GHG 里没有「鬼玩家」，改成冻住母体），CD 25 秒 |
| **传送珍珠** | 末影珍珠 | 右键投掷传送，CD 10 秒 |
| **漂浮药水** | 滞留药水 | 漂浮 **6 秒**、**漂浮Ⅱ**（`items.levitation.duration-ticks` / `amplifier`）；**无冷却**，靠瓶数限速；池子里**加权 3 倍**（`chest-weight`）。两瓶是两件独立道具，用一瓶只消耗一瓶 |
| **凝冰球（通用）** | 雪球 | 从箱子出的那一颗，**无冷却**；砸中母体眩晕 4 秒并让她松手，砸中逃生者减速。和冰球手的**职业凝冰球是两件独立道具**（ID / 冷却分开，互不影响） |
| **冲刺矛（通用）** | 长矛 / 三叉戟 | 右键朝准星突进约 **7–8 格**（`spear-rush.velocity` 1.6），用掉即消失。和突击手的**职业冲刺矛是两件独立道具**。**服务端有「矛」（`GOLDEN_SPEAR`）时用长矛外观，没有就自动用三叉戟，功能完全一致** |
| **选择面板** | 时钟 | **准备阶段专属**，不进箱子。左键或右键打开菜单：逃生者是职业菜单、玩家母体是母体种类菜单；开打自动收走，不能丢 |
| **眩晕药水** | 喷溅药水 | 右键投掷：**砸中母体立刻定身 1.5 秒**（`items.stun-potion.stun-ticks`），期间**不能移动、不能放技能、不能敲箱子**；没砸到就白费一瓶 |
| **臭牛排** | 熟牛肉 | **按住右键真吃**（原版进食动作 + 进度条，松手/换物品会打断），吃完给速度Ⅰ 6 秒 + **自己发光 5 秒**（发光就是代价），另补 **3 点饱食度 + 1 饱和度**（不多，但能垫一口）；饱食度满 20 时和面包一样提示「先消耗掉一点」 |

母体开箱**每个箱子只给一件**，池子是**母体专属**（**狂暴药水**速度Ⅱ 10 秒 / **灵魂探测器** 25 秒内所有玩家发光，CD 35 秒）
加上**人鬼通用**的几件：**冲刺矛 / 凝冰球（通用）/ 传送珍珠 / 漂浮药水**。不会再出现「母体道具 + 人类道具」同箱。这两件加上母体的技能道具与战斧都属于**母体专属**，**不允许丢弃**
（逃生者侧不做这个限制，随手丢道具换空格是被允许的）。

## 九、坐标通报与心跳

**法阵坐标通报**（`hunter.altar.locator`，默认开）：每 **60 秒**把每座**未完成**法阵的坐标
（`法阵 2 位置 X=-128 Z=305`）发给所有逃生者，同时在阵上打一道 10 格高的光柱 + 一记钟声。
法阵点位每局随机，光靠「找」很容易绕圈；坐标加光柱能让队伍快速对齐，也让母体没法靠
「没人找得到」白拿时间。

**心跳**：逃生者靠近母体时能听到**从母体方向传来的心跳**，越近越密、越响：
48 格内 1.5 秒一次 → 贴身 0.23 秒一次，音量随距离 0.9→1.8（`heartbeat.range` 控制半径，
小于 48 一律按 48 格算）。突击手的被动把这条半径乘 1.5。

实现上用的是 `player.playSound(母体坐标, ...)`：声音定位在母体身上，但**只发给那一个逃生者**，
所以**母体本人听不到自己的心跳**，其他远处的玩家也听不到。

## 十一、法阵进度条

对局开始后，**所有逃生者**屏幕上方会有一条粉色 BossBar：

```
法阵破除 0/4 (37%)
```

- 左边是 `已破除 / 总数`，右边是**所有阵的平均进度**——每座阵独立推进，
  所以数字会一座一座往上走（先破一座就 `1/4`），全破后变 `4/4`
- 全部破除后标题变成绿色的 **「法阵全破 —— 去逃脱点撤离」**，条也变绿
- **逃生者与玩家母体都看得到**（`bossbar.show-to-mother`，默认开）——母体需要知道队伍推到哪了，
  才知道该守哪座法阵
- 准备阶段也会显示（0%），让人一眼知道这局有几个法阵
- 关掉用 `hunter.bossbar.altars: false`；BossBar 创建失败时会自动降级成 ActionBar 提示

## 十二、奖池与结算

**奖金只看每个人做了什么，不看哪一方赢。** 奖池（入场费 + 服务器保底）在结算时按**行动分**占比
分给所有真人玩家，玩家母体也是参与者之一：

| 谁 | 行动 | 默认分 |
|---|---|---|
| 逃生者 | 每秒破阵 | 2.0 / 秒 |
| 逃生者 | 每次成功救人 | 15.0 |
| 逃生者 | 成功撤离（额外） | 25.0 |
| 母体 | 每次命中 | 5.0 |
| 母体 | 每次击倒 | 10.0 |
| 母体 | 每淘汰一人 | 40.0 |

- 全部在 `hunter.reward.actions.*` 里可调
- **价位整体偏低**：入场费 50、服务器保底 500（原来是 100 / 3000，保底太高容易刷币），
  钱主要靠行动分挣；母体种类门票也降到 0–180 区间
- **两池制**：逃生者交的入场费（`entryPool`）只在逃生者之间分；**母体只分服务器保底**，
  按她的行动分占比取，**封顶 50%**，剩下的保底也归逃生者。她不再从逃生者凑的钱里拿
- **胜负不再影响奖金**：以前「逃生者赢按贡献分、母体赢整池给母体」，等于奖励阵容
- **时间到判平局**：不计入任何一方胜场，奖金照旧按行动分发（只作为兜底，不让沙漏变成取胜手段）；
  `/ghga hunter stats` 会单独显示平局数
- **对局中断**（管理员强制结束 / 插件禁用）仍**全额退还入场费**
- 逃生者一分行动分都没拿到时，入场费原样退还，不吞
- **被淘汰可以提前结算**：淘汰后 `/ghg leave` 立即按上面的公式把自己那一份算给你
  （奖池 × 自己的分 / 全场逃生者分之和），钱**从奖池里扣掉**，终局结算不会重复发。
  开关 `hunter.reward.early-exit-settle`；没贡献分就只提示一句，不吞奖池
- 测试局不收费、不进统计、不参与分配；正式局（含 AI 母体局）会按抽到的职业收**职业券**

## 十三、安装与运行形态

### 安装

1. 把 `GHG_v1.0.1.jar` 丢进 `plugins/`
2. 需要奖池就装 **Vault** + 一个经济实现（EssentialsX Economy 等）；不装则整块经济功能自动关闭
3. 重启，控制台会出现一张启动表（见下）
4. `/ghga tool` 拿选区工具 → `/ghga pos1` `/ghga pos2` 圈猎场 → `/ghga save <名称>`
5. `/ghga start`（AI 母体）或 `/ghga mode player` + `/ghg join`（玩家当母体）

支持 **Bukkit / Spigot / Paper / Purpur**，Folia 走调度兼容层。
`softdepend: [Gost]` 只是让加载顺序更友善，**不是必需依赖**。

### 启动信息

启动时控制台只打印**一张 GHG 的表**（`StartupReport`），不再沿用 Gost 那套横幅、
「作者 / 主页 / 支持 / 不适用」清单和逐条「已加载 N 个…」。数字全部来自实际配置，形如：

## 十四、命令与权限

### 不想记命令就用 `/ghg`

**`/ghg` 不带参数就是图形菜单**（基岩版玩家直接点，不用敲命令）。结构是「主菜单 → 板块 → 详细功能」，
每个板块能点进一层：

| 板块 | 里面能做什么 |
|---|---|
| **我的状态** | 当前对局阶段、自己的职业、（如果是母体）种类、排队人数、奖池 |
| **对战** | 加入队列 / 离开队列或退出对局 / 查看状态；管理员多两个：排队状态、立即开局 |
| **职业图鉴** | **六种职业全都列**（冰球手也在，AI 母体局会注明「这局用不了」）：道具、技能逐行效果、冷却、被动、职业券。准备阶段点一下直接换 |
| **母体种类图鉴** | 八种母体逐个展开：定位、技能逐行效果、冷却、本局门票、共用被动。玩家母体在准备阶段点一下直接选 |
| **游戏流程** | 四页说明：一局流程 / 交互与法阵 / 击倒与椅子 / 胜负与分钱 |
| **语言** | 六种语言点一下就切，选项用该语言自称（English / 日本語 / …） |
| **命令一览** | 玩家命令表；有 `ghg.admin` 时再给一张管理员表 |
| **管理员调试**（仅 `ghg.admin` 可见） | 24 个常用数值直接加/减，外加**热重载**、强制收局、清空队列、立即开局 |

菜单里的排队、退出、状态这些动作走的都是原命令（`performCommand`），所以**行为与命令完全一致**，
不存在「菜单能做、命令做不到」的第二套逻辑。界面文案全部走语言文件；万一某个键真的没配，
菜单会显示一个中性占位符并在控制台警告，**不会把 `menu.xxx` 这种裸键摆到玩家眼前**。

> 「管理员调试」板块里那 24 个格子**故意**用原始配置键当名字（`hunter.duration` 这种）——
> 那是给管理员对的，玩家看不到这个板块（需要 `ghg.admin`）。

**管理员调试板块**是唯一直接改配置的地方，规则如下：

- 每格一个配置键，格子的名字就是**原始键路径**（`hunter.duration` 这种），
  鼠标停上去能看到当前值、取值范围和步长
- **左键 +1 步 / 右键 −1 步 / 按住 Shift 再点 ×5**；改完立刻写进 `config.yml` 并落盘
- 写的是**真实配置**，不是内存覆盖——服务器重启后改动还在，也不会和自己的 config 打架
- **热的部分立刻生效**：法阵涨速、守机回落、加固时长、衰减半径、救援/自愈读条、箱子补货、
  心跳半径、奖池、队列门槛这些每 tick 或每次判定时现读的键，改完就是新值；
  对局时长会当场重算；**母体移速、法阵数量、箱子初始个数是开局时读的，下一局生效**
- 格子可以调：对局时长、准备时间、法阵数量 / 涨速 / 守机速度 / 加固时长、撤离读条、终局倒计时、
  箱子数量与补货、击倒次数、倒地自愈、救援读条与保护、自愈秒数、椅子两次倒计时、
  母体移速 / 攻击冷却 / 索敌半径、心跳半径、入场费、保底奖金、排队门槛
- 底部那一行是动作：**热重载配置**（等同 `/ghga reload`，重读 `config.yml` 与猎场数据）、
  强制收局、清空队列、立即开局

### 管理命令

需要 `ghg.admin`。**`hunter` 可以省掉**：`/ghga start` 和 `/ghga hunter start` 完全等价，
两条路走同一个 handler，老写法照旧可用。

**「谁来当母体」有两种模式**，用 `/ghga mode` 随时切换（也可以直接改 `hunter.queue.mother`）：
`AI`（默认）队列只排逃生者、开局刷 AI 母体；`PLAYER` **从队列里随机抽一人当母体**（不看入队顺序）。
切到 `PLAYER` 前要保证 `hunter.mother.player-mode.enabled: true`，否则指令会拒绝并告诉你原因。

| 命令 | 说明 |
|---|---|
| `/ghga start [玩家...]` | 开局（AI 母体）。不带玩家名时取**游戏区域内的所有玩家** |
| `/ghga mother <母体玩家> [逃生者...]` | 用**玩家**当母体开局 |
| `/ghga kind` / `kind <种类>` | 打开种类菜单 / 直接指定种类 |
| `/ghga stop` | 强制结束当前 GHG 对局 |
| `/ghga queue` | 查看排队状态（谁在排、凑人还是倒计时、还剩几秒） |
| `/ghga queue start` / `stop` | 跳过倒计时立即开局 / 清空队列 |
| `/ghga mode` / `mode ai` / `mode player` | **切换母体模式**（写进 `hunter.queue.mother`，下一局生效）：`ai` = 队列只排逃生者、开局刷 AI 母体；`player` = **从队列里随机抽一人当母体**。对局进行中不让切；切的时候会清空并通知已有队列 |
| `/ghga status` | 打印准备/法阵/撤离/击倒/母体种类（也是插件总状态） |
| `/ghga stats [条数]` | 查看最近对局数据与累计胜率（默认 5 条） |
| `/ghga test` | **单人试玩**：自己当唯一逃生者，AI 母体正常追（不收费、不进统计、不自动收局） |
| `/ghga test mother` | **单人试玩（当母体）**：自己是母体，人类侧用会跑的测试假人代替 |
| `/ghga testmother` | 测试局里切换 AI 母体「追 / 站桩」 |
| `/ghga charge [百分比]` | 把**所有未完成的法阵**设到这个进度（默认 **10%**，带不带 `%` 都认；`100` = 直接充满破除）。只推进度，**不触发瘫痪** |
| `/ghga down` / `kit` | 测试辅助（强制倒地、发一套道具） |
| `/ghga pos1` `/ghga pos2` | 选区两个角 |
| `/ghga save <名称>` / `list` / `load` / `delete` / `info` / `clear` | 猎场管理（`load` 后下一局强制使用该猎场） |
| `/ghga tool` | 拿选区工具 |
| `/ghga giveitem <道具ID>` | 发一件道具，参数是稳定 ID，如 `ritual-knife` |
| `/ghga selftest` | 运行期自检（单人可跑，不用开局） |
| `/ghga reload` / `status` / `lang` | 维护 |

权限：`ghg.admin`（管理员，默认 OP）、`ghg.use` / `ghg.player` / `ghg.join` / `ghg.leave`
（玩家，默认都有）。

**母体测试用的假人不是摆设**：它们是关掉原版 AI、由插件**每刻**推一次速度的 villager ——
（原来 4 刻推一次，速度每刻被地面摩擦吃掉一半，结果就是「几乎不动」）
母体进了 `dummy-flee-range`（默认 14 格）就朝反方向跑 `dummy-flee-distance`（默认 8 格），
速度由 `dummy-flee-speed`（默认 0.14，约 2.8 格/秒，**刻意比母体慢**）控制；
**连跑 `dummy-flee-seconds`（默认 3 秒）后会体力耗尽，站着喘 `dummy-tired-seconds`（默认 2 秒）** ——
这段就是母体真正能砍到它的窗口（以前它一直跑、速度还和母体相当，测试时一刀都打不着），
平时在附近小范围游荡；前方一格被挡住时**只在落地那一下**给跳跃冲量翻过去。
万一生成在石头缝里彻底卡死，会被**挪到旁边能站的地方**（只对假人做，玩家和母体绝不移位）。它们**不是无敌的**（无敌就收不到伤害事件），
而是靠监听器把伤害 `setCancelled`：所以母体砍上去有击退、有红叉粒子、有受击音，
头顶名字实时显示还剩几下，打够 `dummy-hits`（默认 2）下倒地、1 秒后补新的。

## 十五、开局前的准备（猎场圈地）

GHG 不会自己造地图，需要先圈一块**猎场**。这套圈地是 GHG 自己的：
数据落在 `plugins/GHG/areas.yml` 与 `plugins/GHG/enabled_areas.yml`，命令全在 `/ghga` 下，
命令空间与 Gost 的 `/gostadmin` 分开，两者同时安装也不会激活同一套对局。

选区工具是**小麦**（`area.tool-material`，默认 `WHEAT`）：

```
/ghga tool            # 拿选区工具（小麦，名字叫「GHG 猎场选区工具」）
左键点一个角 → 右键点对角
/ghga pos1 / pos2     # 或用命令手动设点
/ghga save 猎场1       # 存成猎场（新建的猎场**默认未启用**）
/ghga load 猎场1 enable   # 启用它，否则开局抽不到这张图
/ghga list            # 确认它在列表里、且前面标着「已启用」
```

`/ghga load <名称>` 不带第三个参数是「下一局就用这张」；带 `enable` / `disable` 才是改启用状态。
`area.random-each-game: true`（默认）时，每局从**所有已启用**的猎场里随机抽一张。

> `area.selection-tool` 是 Gost 时代的旧键，GHG 已经不读了（它的值多半还是岩浆膏）。
> 想换工具材质改 `area.tool-material`。

**猎场保护**：`area.protection: true`（默认开）——不在对局里、又没有 `ghg.admin` 权限的玩家，
**不能在猎场范围内挖方块或放方块**（会提示「这里是 GHG 猎场」）。对局中的玩家不受这条影响
（道具箱、栅栏、法阵地砖都靠他们自己动），管理员始终可以改。

区域定下来之后，法阵 / 逃脱点 / 道具箱的位置**全部自动算**：

- 包围盒切 **3×3 九宫格**当候选池，**每局随机抽**法阵位与逃脱点（逃脱点避开法阵 4 格内）
- **局内固定、局间不重复**：玩家能记住、母体能预判，十局又不是同一张图
- `area.random-each-game` 默认开：每局从**已启用**的猎场里随机选一张；
  `/ghga load <名称>` 手动指定的只对下一局生效
- 调试固定地形时把 `hunter.points.randomize` 设成 `false`，退化成固定矩阵
- 道具箱在包围盒 15%–85% 区间随机

高度上有两条规则：

- **多层猎场**（`hunter.points.multi-floor`，默认开）：每一列从阵地底部到「区域顶部再往下 2 格」之间，
  **所有能站人的地面都算候选**（一层、二层、阁楼、平台），每局随机挑一层。所以二层、三层都能出法阵，
  不用再把整个猎场压成一层
- **顶层保护**：法阵 / 逃脱点 / 地窖的 Y **不许落在区域顶部 2 格以内**（选区的 Y 跨度小于 8 格时
  视为「只在地面上点了两块」，不设这道限制）—— 那一层通常是屋顶或顶层木板，落上去玩家够不着

关掉 `multi-floor` 就退回老行为：只跟「发起者站位那一层」，候选与它高度差超过
`hunter.points.max-height-diff`（默认 0 = 不限；关掉多层后按固定 12 格）的会被排到后面。
开图前建议把猎场地面整平、别放栅栏迷宫（母体虽然有跳跃提升Ⅲ 和原地脱困，能少卡就少卡）。

**法阵长什么样**：法阵格地面铺成地砖（未充能**粉红色染色玻璃** → 破除后海晶灯；被加固时哭泣的黑曜石），外圈哭泣的黑曜石边框，
加常驻旋转粒子环与向上的 END_ROD 光柱；被玩家母体砸过的格子是**哭泣的黑曜石**（加固中）。
所有改动逐块记录原始材质，**对局结束全部还原**。

改配置结构时三件套一起走：`ConfigManager.CURRENT_CONFIG_VERSION + 1`、CHANGELOG.md 记一笔、
确认 `resources/config.yml` 里的新键。当前配置版本 **31**，键名是 **`ghg-config-version`**
（GHG 自己的，与 Gost 的版本号无关，从 1 起算）。

版本不匹配时会自动迁移：先把 config.yml 备份成 `config_old_v<旧版本>.yml`，再按新默认配置重写，
然后把旧配置里的键**逐个全部写回**——丢掉用户手改过的键是不可接受的。随后按版本号跑一遍
「只改仍是旧默认值的键」的调参链（v2 对局时长、v5 票价、v6 自愈、v7 法阵上限、v10 母体移速…）。
纯新增键的版本（比如 v15 的排队开局）不用写迁移代码：新配置按模板长出来，旧值再逐个写回。

例外是 **v9 的配置瘦身**：那一步会以 jar 内的 `config.yml` 当白名单，把 Gost 时代的死键
（感染 / 猎魔人 / 鬼粒子 / `hunter.vault` …）**删掉**。所以想找回任何一个被删的键，
去 `config_old_v*.yml` 里抄。

## 十七、状态还原（背包快照）

入局时会把每个人的**游戏模式 / 坐标 / 背包 + 护甲 / 血量 / 饱食度 / 等级经验 / 飞行状态**
存成一份快照，离场时原样还回去。三条路径都覆盖：

| 场景 | 处理 |
|---|---|
| 正常收局 / 管理员强制收局 | `stop()` 遍历参赛者还原，**阵亡变旁观的人一并还原**（生存 + 原位 + 原背包） |
| 对局中退服 | `PlayerQuitEvent` 里当场还原（此时服务器还没落盘玩家数据，所以退服位置也是原位） |
| **服务器崩溃 / 被强杀** | 快照同时写在 `plugins/GHG/player-states.yml`，重启后玩家上线**自动还原**，还原成功即删除记录 |

另外两道兜底：

- **进服检查**：不在对局里却还挂着旁观的人，直接切回生存；人还在猎场里就送出猎场边缘
  （管理员在猎场外挂旁观视为在看局，不动）
- **清空背包前**：若快照因为任何原因不存在，立刻补存一次——绝不出现「背包已清、快照没存」
- `/ghga selftest` 会报「未归还的背包快照 N 份」，不为 0 就说明上次没正常收局

快照记录带时间戳，超过 **7 天**的残留记录在启动时自动丢弃，不会拿一周前的旧背包盖掉玩家现在的东西。

## 十八、对局数据

每局结束会把关键数字写进 `plugins/GHG/hunter-stats.yml`（只保留最近 200 局），
并在结算时广播一段摘要：

```
本局结算 | 逃生者全灭
用时 3:07 / 上限 20:00 | 法阵 1/4 | 击倒 3 | 命中 5 | 救援 1
淘汰 阿丙 · 下一局 /ghga hunter start
```

`/ghga hunter stats [条数]` 看累计：总局数、逃生胜 / 母体胜 / 平局、**逃生胜率**、平均时长，
以及最近每局的明细（时间 / 时长 / 区域 / 法阵 / 击倒 / 救援 / 结果）。

调参数就看这几个数：胜率长期偏向母体，说明逃生者缺「换时间」的手段；平均时长过短，
说明破阵太快或母体太弱；法阵 charged/total 长期停在 0，说明根本没人摸到法阵。

## 十九、与 Gost 的关系

玩法与代码来源：

- **玩法**：借鉴 **《黎明杀机》**（猎杀 / 修机 / 搬运 / 救援 / 终局撤离）与
  **《第五人格》**（法阵献祭、狂欢椅式的搬运淘汰、地窖）
- **代码**：**部分原代码取自 Gost** —— 道具框架（`ItemIds` / `ItemEffectRegistry`）、
  区域圈地、多语言、跨版本兼容层与自检都是从那边沿用下来的，再按 PvE 玩法重写上层
- **后续**：计划做一次代码检查，把不再被引用的多余部分（经典局残留、死配置、死语言键提示之外的死代码）清理掉。
  目前的可运行遗留见第二十一节「已知缺口」

改造过程中还了三笔技术债：

1. **道具身份 → PDC 稳定 ID**
   原来全项目靠 `displayName.contains("中文名")` 判断道具是什么，改语言就全失配。
   现在创建道具时写入 `PersistentDataContainer` 的 `item_id`，判定一律读 PDC，
   旧存档没有 PDC 时按中文名兜底一次（`ItemIds.legacyIdOf`）。
   道具显示名已进语言文件（`item-name.*`），**lore 仍是中文**，这是已知缺口。

2. **道具效果 → `ItemEffect` 注册表**
   效果从 `ItemListener` 的 if-else 分支抽成 `ItemEffect` 实现，注册进 `ItemEffectRegistry`，
   任何地方都能 `registry.use(player, item, 右键, 左键)` 单点触发，冷却也收在注册表里。
   没注册效果的道具**不拦原版动作**（否则会出现「面包吃不了」这类问题）。

3. **对局模式上下文 → `MatchMode`**
   `IDLE / CLASSIC / HUNTER` 三态，由 `ModeManager` 唯一持有。监听器入口先判模式再处理，
   否则两套规则会打架。进入模式是抢占式的：GHG 在跑时开不了经典局，反之亦然。

另外顺手修的：`ServerCompat.teleportSafely` 现在优先走 `teleportAsync`
（Folia 上跨 region 的同步 `teleport()` 会抛异常），`teleportPlayerToArea` 也改走它。

- **痕迹只有一种可见性**：抓痕与血迹用的是粒子，**全服可见**——做不到「只有母体看得见」，

- **道具 lore 本地化**：仍硬编码中文（显示名走语言文件）
- **平局不进胜率分母**：`/ghga hunter stats` 会单独显示平局数，但胜率只按有胜负的局算
- **视觉技能的副作用**：窥视者的透视用的是 `GLOWING`，MC 里发光是**全服可见**的，
  所以被透视时其他逃生者也会看到同伴在发光
- **母体会被清理插件影响**：EClean 之类会清生物，已加看门狗（1 秒内补刷），但补刷位置在幸存者附近

- **内置配置模板的版本号仍是 1**：所以**首次安装**会走一遍 v1→v14 的迁移链，并在数据目录留下
  一份 `config_old_v1.yml`。数值最终会收敛到当前默认，只是多一个备份文件
- **启动表里的「自动投放池 4 种」是死数据**：天降投放系统已经封了，道具只从道具箱出，
  这一行只是 `ItemSpawnManager` 里遗留的计数

# English

## 1. Anatomy of a match

### 0. Queue (`/ghg join`)

Players join a queue instead of asking an admin to start. A blue boss bar shows
`players / required`; when enough people are in, a countdown starts and the match begins.
Queue times and thresholds live in `hunter.queue.*`.

- `/ghg leave` while queued only leaves the queue (it does **not** report "you are not in a match")
- A match that is already running refuses `/ghg join` and tells the player to use `/ghg spectate`
- In `PLAYER` mother mode **one player is picked at random** from the queue to be the Mother —
  joining first gives you no advantage (`/ghga mode` switches between `ai` and `player`)

### 1. Preparation (default 25 s)

- Survivors move freely, scout the map and check the terrain
- **Altars cannot be charged yet** (standing on one does nothing)
- The **Mother is held in place**; a player Mother picks her kind here, survivors pick their **role**
  (the role menu opens automatically, `/ghg role` also works)
- **Items are locked** during preparation — only the **Selection Panel** (see below) is usable
- **Hunger does not drain** during preparation: food and saturation are pinned full every second
- Every participant receives a **Selection Panel** (a clock). **Left- or right-click** opens the
  matching menu — role menu for survivors, kind menu for a player Mother — so closing the UI does not
  force you to type a command. It cannot be dropped and is removed automatically when the match starts
- Chests are already spawned; breaking them is allowed (loot is part of preparation)
- The last 5 s lock the Mother kind (`kind-lock-seconds`) and show a centred countdown

### 2. Hunt phase

The Mother is released. Survivors **hold Shift** on any uncharged altar tile —
**each altar keeps its own progress bar**. Charge rate = base **1.8 %/s** × 0.9 × the summed role
weights of the **first two** chargers (single ordinary role **1.62 %/s**, ~**62 s** to fill;
Engineer **2.03 %/s**, ~49 s; **two people add their weights together**, ~31 s).
A third person is not counted and is told the altar is full.

The Mother suppresses an altar by entering its **6-block** radius (**−1.5 %/s**): for an ordinary
role the net is **+0.12 %/s**, i.e. **slower but no longer negative** (raise `decay-per-second`
above 2.0 to restore the old "progress goes backwards" behaviour).

Every **0.5 s** a clicking sound plays while somebody charges (`charge-tick-ticks`), rising in pitch
with progress.

An altar stops at **20 %** once and is **paralysed for 60 s** — nobody can charge it, the Mother
cannot harden it.

The last 5 s before the hunt show a mystery subtitle ("Mother: ??? · kind locked"); the real kind and
skill are only revealed at the starting whistle (chat + title).

### 3. Escape phase

When every altar reaches **100 %** they all break at once; the system picks **one of the freshly
broken altars at random** as the escape point and announces it. Hold **Shift** there for
`escape.hold-seconds` (4 s) to escape.

At the same time the **endgame countdown** starts (`endgame.seconds`, default 90 s); anyone still
inside when it ends is buried with the Mother.

> The escape point never exists at match start and never glows beforehand, and it is **never the last
> altar that broke** — that would let a survivor walk out from the tile they were just standing on.

**One survivor walking out ends the match**: everyone alive and not eliminated counts as escaped —
they do not need to queue up at the same point.

### 4. Lone-wolf hatch

With only **1 survivor** left, a **hatch** opens (its coordinates are broadcast) and holding Shift
lets that player leave alone. The hatch point is **one of the altars picked at random**; no extra
structure is generated.

## 2. Everything uses Shift

GHG is designed so that a Bedrock/Geyser player can play with a single key:

| Action | How |
|---|---|
| Charge an altar | **Hold Shift** while standing on an altar tile |
| Pick up / rescue a downed teammate | **Hold Shift** next to them (3 s, radius 2.5) |
| Heal a teammate / heal yourself | **Hold Shift** next to them (8 s) / **hold Shift** alone (20 s) |
| Escape | **Hold Shift** at the escape point for 4 s |
| Struggle out of the Mother's grip | **Hold Shift** while carried (8 s) |
| Mother: grab a downed survivor | **Hold Shift** next to a downed survivor |
| Mother: axe attack | **Left click** (must hold the Mother's Axe) |
| Mother: cast skill | **Right click** (must hold the skill item) |
| Mother: harden an altar | **Left click** 16 times on the pink stained-glass tiles |
| Engineer: place fence | **Right click** (Fence Kit) |
| Use an item | **Right click** (locked during preparation). **Left click never triggers an item** — the extra click while breaking a chest no longer fires pearls, clocks or potions |
| Re-pick role / Mother kind | **Left- or right-click** the clock (Selection Panel) |

## 3. Rule details

**Each altar has its own progress bar.** You charge the altar you stand on; at 100 % that single altar
breaks, and the escape point only opens when **every** altar is broken. That turns "which altar next"
into a real decision: spread out to share risk, or focus one down.

- **Altar count**: default **4** (`altar.count`, 1–8; `0` = `ceil(players/2)` capped by `altar.max`)
- **Charge rate**: `progress-per-second × 0.9 × summed weights of the first `max-chargers` (2) chargers`,
  base **1.8 %/s**. Ordinary role **1.62 %/s** (~62 s solo), Engineer 1.25 → **2.03 %/s** (~49 s),
  two people roughly double it. A third charger is ignored and told the altar is full. The
  `group-bonus` key is kept but no longer read
- **Suppression**: the Mother inside `decay-radius` (6 blocks) drains that particular altar at
  `decay-per-second` (1.5 %/s). **Since the charge base is 1.8, an ordinary role still gains
  +0.12 %/s — slowed, not reversed**; raise `decay-per-second` above 2.0 to bring back the reversal
- **Paralysis**: the first time a single altar crosses `paralyze.at` (20 %) it stops for
  `paralyze.seconds` (60 s): no charging, the Mother cannot harden it, and the tiles turn **grey glass**.
  It triggers only once per altar; the pink glass comes back when it ends
- **Hardening**: the **player** Mother breaks the **pink stained-glass** altar tiles **16 times**
  (`harden-hits`; more than 10 s without a hit resets the count) → that altar is **hardened for 50 s**
  and has a **60 s cooldown** before it can be hardened again. During hardening nobody can charge it.
  AI Mothers never harden
- **Boost during hardening**: while an altar is boosted by the Ritual Stone it **cannot be paralysed**;
  the paralysis is triggered the moment the boost expires
- **Escape point**: picked at random from the freshly broken altars (never the last one); leaving
  resets the hold. The endgame countdown gives the Mother a last chance
- **Downing**: two hits from the Mother → the survivor **goes down** (crawling pose), cannot move and glows
- **No slow on being hit**: being hit gives **Speed II for 2 s** (burst), then **Slowness I 1.5 s**
  (exhaustion). Sprinting is disabled and the Mother is faster, so without this a chase would be lethal
- **Mother recovery**: after a hit she is **Slowness IV for 2 s** (no chase, no attack, no skill), and
  the **axe vanishes, returning 3 s later**. Only the axe comes back — the skill item waits for its own
  cooldown (otherwise you would hold an item that does nothing)
- **Injured state**: one hit without being downed is **injured** — the survivor **bleeds** (dark-red
  particles) and can be healed. Being rescued leaves you **injured**, not full health
- **Healing**: a teammate holds Shift for **8 s**; healing yourself takes **20 s** and needs
  **food ≥ 8**. Interrupting rolls progress back
- **Self-recovery from downed**: with nobody helping, after **15 s** you crawl back to **injured**
- **Altar Sacrifice** (on by default): the Mother can **carry** a downed survivor to any uncharged altar
  and pin them there — **that altar stops working** (nobody can charge it) while the countdown runs:
  **60 s**, then **30 s**, then **explodes after 5 s**. Teammates hold Shift for **4 s** to tear the
  altar open and free them. While carried, holding Shift for **8 s** breaks you free
- **Rescue is a channel**: a teammate holds Shift for **3 s**; letting go, walking away or being
  downed interrupts it
- **Rescue protection**: 3 s of immunity to the Mother's hits after being freed
- **At most 1 rescue per player per match** (`rescue-limit`)
- **Both the rescued and the rescuer glow** for a short while (4 s)

> Keep the glow short. Minecraft's glowing effect is **visible to the whole server**; there is no way to
> show it only to teammates, and a long glow turns "downed" into "eliminated" and lets people follow it
> to the rescuer.

## 4. Key numbers

| Item | Value |
|---|---|
| Match length | **900 s (15 min)** (`hunter.duration`); hitting the cap is a draw |
| Preparation | **25 s**; items locked, hunger pinned full, Selection Panel in hand |
| Survivors | 1 Mother vs up to **4** survivors |
| Altars | **4** by default (1–8); single role **1.62 %/s**, two people **~31 s** per altar |
| Altar paralysis | first crossing of **20 %** → **60 s** |
| Hardening | **16** broken tiles → **50 s** hardened, **60 s** cooldown |
| Ritual Stone | **×2** charge speed for **20 s**, item consumed, **30 s** cooldown |
| Paralyse vs boost | a boosted altar cannot be paralysed; it is paralysed when the boost ends |
| Escape hold | **4 s** (radius 3) |
| Downing | **2** hits; rescue channel **3 s** (radius 2.5); **1** rescue per match |
| Rescued state | **injured** (needs healing) |
| Healing | teammate **8 s** / self **20 s** (needs food ≥ 8) |
| Self-recovery | **15 s** |
| Health display | healthy **10 hearts**, injured **3 hearts**, downed **1 heart** (display only) |
| Altar Sacrifice | **60 s / 30 s / 5 s**, struggle **8 s**, rescue **4 s**, AI camps **10 s** |
| Hunger | survivors get **Hunger II** every 2 s; starting saturation **5**; food ≤ 6 adds Slowness I |
| Mother speed | movement speed **0.26**; axe cooldown **4 s**; recovery **2 s** @ Slowness IV |
| Spectating | `/ghg spectate`; movement limited to the arena **X/Z ± 10 blocks** |
| Early exit | eliminated players can `/ghg leave` and settle their share immediately |

## 5. Altar Sacrifice

Instead of bleeding out on the floor, a downed survivor can be **carried to an altar and pinned there** —
the moment a body is pinned, **that altar stops working**: nobody can charge it and the Ritual Stone does
nothing on it. Freeing the survivor restores the altar.
This is the only elimination path in GHG (`hunter.chair.enabled: false` falls back to bleed-out).

- The pinned player hears a countdown and the whole lobby sees who was pinned on which altar
- Teammates holding Shift for **4 s** tear the altar open and rescue the survivor
- The countdown runs **60 s → 30 s → explodes 5 s after the third pin**
- AI Mothers camp the altar for **10 s** before leaving

## 6. Survivor roles

A role is assigned at random each match and can be changed on the preparation menu (paying/refunding
the difference in role tickets). A role decides both the **active skill item** and a **passive tendency**:

| Role | Skill item | Cooldown | Passive | Ticket |
|---|---|---|---|---|
| **ICER** | Ice Ball: hitting the Mother stuns her for **4 s** and makes her drop a carried survivor (the common Ice Ball from chests is a **separate item**). **Not offered when the Mother is AI** | 55 s | — | 80 |
| **GUARDIAN** | Redemption Charm: rescue channel **×3** for 15 s | 45 s | rescue/heal channel **×1.3** | 60 |
| **LANCER** | Spear Rush: short dash, velocity **1.6**, ~**7–8 blocks** (the common Spear Rush from chests is a **separate item**) | 40 s | heartbeat range **×1.5** | 60 |
| **ENGINEER** | Fence Kit: right-click to place a wood fence | 45 s | faster charging: weight **×1.25** (**2.03 %/s**) | 40 |
| **RUNNER** | Adrenaline: **Speed I for 4 s**, then **1 s of slowness** (weakened on purpose) | 35 s | — | 40 |
| **WRAITH** | Shadow Cloak: **invisible for 6 s**. The Mother's passive sight still outlines you (glowing beats invisibility), so it hides you from sight, not from her | 40 s | — | 50 |

**Engineer's fence**: right-click places `fence-width × fence-height` (3×2) fence blocks at the crosshair.
It can only be placed inside the arena and only replaces air/water/grass. It takes `fence-hits` (3) hits
to break — the Mother and any Engineer can break it; the **AI Mother will ram it** (once every 0.5 s)
instead of getting stuck.

## 7. Mothers: eight kinds

| Kind | Skill | Effect | Cooldown | Ticket |
|---|---|---|---|---|
| `SPRINTER` | Sprint | **Speed I for 6 s** | 20 s | free |
| `CHARGER` | Dash | A player Mother dashes **where you aim** (works with nobody nearby); the AI dashes at the nearest survivor. Power **2.6** (~8–9 blocks); a **1.6 s** window (32 ticks) turns contact into a **2 s stun** (radius 2.2). **The Mother gets no debuff** | 16 s | 100 |
| `ARCHER` | Arrow | **Pure hit**: a hit counts as a normal hit toward the 2-hit down, **no slow at all**; a player Mother shoots **at the crosshair** | 16 s | 120 |
| `ALCHEMIST` | Bolt | Fires a bolt that **splashes potion on impact**: survivors within **3 blocks** get **Slowness I for 3 s**; a player Mother aims at the crosshair | 18 s | 100 |
| `WALKER` | Teleport | A player Mother **blinks toward the crosshair** up to `teleport.distance` (8); the AI teleports **1.8 blocks behind its target**. Both suffer **2 s of freeze** | 28 s | 150 |
| `WATCHER` | Vanish | **Invisible + Speed II for 7 s**; landing a hit **cancels the speed** (invisibility stays) | 28 s | 180 |
| `WEAVER` | Snare | Throws a splash potion around itself; survivors within **7 blocks** get **Slowness I for 3 s** | 18 s | 120 |
| `PEARL_LADY` | Pearl Teleport | The Mother version of the teleport pearl: blinks up to **10 blocks** toward the crosshair (AI blinks 1.6 blocks behind its target). Landing applies **Slowness I for 4 s**; **hitting a survivor clears it instantly** and replaces it with the 2 s attack recovery | 24 s | 160 |

> Skill items behave like survivor role items: the item **disappears the moment it is used** and is
> handed back by `tickMotherSkillItem()` once the cooldown is over. **This rule is global**: axe recovery,
> match-start refresh and switching kind in a test match never hand you a skill item while it is cooling
> down. Cooldowns are `hunter.mother.skills.<skill>.cooldown`, overridable globally with
> `hunter.mother.skill-cooldown`.

> **Direction depends on who casts**: a player Mother always aims with the crosshair — dash goes where you
> look, arrows/bolts shoot where you aim, teleport blinks toward your crosshair (landing spot searched from
> far to near). Nothing is auto-targeted for you. Only an AI Mother receives a target from `MotherBrain`.

### Shared passives

All Mother kinds share:

- **Passive sight**: standing still for **3 s** makes survivors in range glow (wallhack for a moment).
  Moving cancels it and it has to be built up again
- **Traces**: injured/downed survivors leave dark-red particles, moving survivors leave dust at their feet.
  Particles are visible to everyone — there is no per-player visibility without packet work
- **Jump boost III** (AI only) and the ability to break fences
- **Chest opening**: an opened chest gives **exactly one** item, drawn from the Mother pool (Frenzy Potion /
  Soul Detector) **plus** the shared combat items (Spear Rush / common Ice Ball / Teleport Pearl /
  Levitation Potion)

## 8. Items and supply

**Items only come from chests** — nothing is dropped on the ground. A chest is a **melon**
(`chest.material`) that takes **5 hits** and gives **2 items**, both drawn from the weighted pool
(rations are **no longer guaranteed** — food is something you have to find).

Survivor pool (`ItemIds.survivorPool`; role skill items are **not** in it):

| Item | Material | Effect |
|---|---|---|
| **Emergency Ration** | bread | **Hold right-click to actually eat**, one bite per ration, each bite restores 6 food + 4 saturation. **Stackable**, no longer guaranteed. Weight **4** in the pool |
| **Medkit** | honey bottle | Right-click **instantly heals an injury** |
| **Ritual Stone** | flint | Right-click on an altar: **×2** charge speed for **20 s**; consumed, **30 s cooldown**; useless while hardened/paralysed |
| **Soul Control** | clock | **Freezes the Mother for 4 s**, cooldown 25 s |
| **Teleport Pearl** | ender pearl | Throw to teleport, cooldown 10 s |
| **Levitation Potion** | lingering potion | Levitation **6 s**, **level II**, **no cooldown**; weight **3**. Two bottles are two items, and using one consumes one |
| **Common Ice Ball** | snowball | The chest version, **no cooldown**; hitting the Mother stuns her 4 s and makes her drop a carried survivor, hitting a survivor slows them. **Separate from the ICER role item** |
| **Common Spear Rush** | spear / trident | Dashes ~**7–8 blocks** toward the crosshair, consumed on use. **Separate from the LANCER role item**. **Uses the spear model when the server has `GOLDEN_SPEAR`, otherwise falls back to the trident — identical behaviour** |
| **Stun Potion** | splash potion | Throw it: **hitting the Mother pins her for 1.5 s** — she cannot move, cast, open chests or use items. A miss wastes the bottle |
| **Selection Panel** | clock | **Preparation-only**, never in chests. Left/right-click opens the role menu (survivors) or kind menu (player Mother); removed at match start, cannot be dropped |
| **Stinky Steak** | cooked beef | **Hold right-click to actually eat** (vanilla animation + progress bar); grants Speed I 6 s + **self-glow 5 s** (the glow is the price) and restores **3 food + 1 saturation**. Cannot be used at full hunger |

The Mother's chest pool is **Frenzy Potion** (Speed II 10 s) or **Soul Detector** (all players glow for
25 s, cooldown 35 s), plus the four shared combat items above. Mother-only items (Frenzy / Soul Detector /
skill item / axe) **cannot be dropped**.

## 9. Altar pings and heartbeat

**Altar pings** (`hunter.altar.locator`, on by default): every **60 s** every uncharged altar's
coordinates are sent to all survivors, with a 10-block beacon beam and a bell. Altar spots are randomised
per match, so pings keep a team aligned (and stop the Mother from getting free time by "nobody finds them").

**Heartbeat**: survivors hear a heartbeat **coming from the Mother's position**, faster and louder the
closer she is: 1.5 s intervals at 48 blocks → 0.23 s when adjacent, volume 0.9→1.8
(`heartbeat.range`, anything below 48 is treated as 48). The LANCER passive multiplies this range by 1.5.

It is implemented with `player.playSound(motherLocation, ...)`: the sound is positioned on the Mother but
**only sent to that survivor**, so she never hears her own heartbeat and distant players hear nothing.

## 10. Particles and sounds

Particles refresh **every 4 ticks** (5× finer than once per second) and can be tuned or disabled under
`hunter.particles`:

| Where | Effect |
|---|---|
| Altar ring | a circle sampled at 16 points; brighter while being charged |
| Charging | the survivor **glows continuously** (renewed every 4 ticks, fades 12 ticks after letting go); the altar centre emits enchant particles |
| Suppressed altar | darker/red particles while the Mother camps it |
| Downed | crawl pose, constant glow, bleeding particles |
| Traces | dust while moving, blood when injured |
| Sounds | altar milestones (note block pling every 10 %, pitch rising), charge clicks every 0.5 s, bell on breaking, dragon growl at match start, heartbeat, item sounds |

Sound resolution is centralised in `SoundCompat`: every sound has a modern name plus legacy aliases, so the
same jar works from 1.20.x through current Paper/Purpur. `/ghga selftest` resolves **all 34** of them and
lists the ones the server cannot find (an unresolvable sound fails **silently** at play time).

## 11. Altar boss bar

A boss bar shows `broken / total` on the left and the **average progress of all altars** on the right —
each altar advances independently, so the average reflects the whole team. New milestones play a note and
the bar colour shifts. Toggle with `hunter.bossbar.altars`.

## 12. Prize pool and settlement

**Money depends on what you did, not on which side won.** The pool (entry fees + server bonus) is split by
**action score** among all real players; a player Mother is one of them:

| Who | Action | Default score |
|---|---|---|
| Survivor | per second charging | 2.0 / s |
| Survivor | per successful rescue | 15.0 |
| Survivor | escaping (bonus) | 25.0 |
| Mother | per hit | 5.0 |
| Mother | per down | 10.0 |
| Mother | per elimination | 40.0 |

- All weights live in `hunter.reward.actions.*`
- **Deliberately low stakes**: entry fee 50, server bonus 500 (was 100 / 3000 — too easy to farm);
  Mother kind tickets also dropped to the 0–180 range
- **Two pools**: entry fees (`entryPool`) are split among survivors only; the **Mother only draws from the
  server bonus**, proportional to her action score and **capped at 50 %**. She no longer takes money that
  survivors paid in
- **Winning no longer determines payout** (it used to be "survivors win → split by contribution, Mother wins
  → whole pool to her")
- **Time-up is a draw**: neither side gets a win, money is still split by action score
  (`/ghga hunter stats` shows the draw count separately)
- **Aborted matches** (admin force-stop / plugin disable) refund the entry fee in full
- If a survivor scored nothing at all, the entry fee is returned rather than swallowed
- **Eliminated players can settle early**: after being eliminated, `/ghg leave` immediately pays their share
  (pool × own score / total survivor score) and **deducts it from the pool**, so the final settlement does
  not pay twice. Toggle: `hunter.reward.early-exit-settle`
- Test matches take no money, do not enter the stats and do not distribute prizes; real matches (including
  AI-Mother matches) charge the **role ticket** of the assigned role

**The test dummies are not decoration**: they are villagers with vanilla AI disabled, pushed by the plugin
**every tick** (a 4-tick interval let ground friction eat the velocity, which made them look motionless).
When the Mother comes within `dummy-flee-range` (14 blocks) they run the opposite way for
`dummy-flee-distance` (8) at `dummy-flee-speed` (0.14 ≈ 2.8 blocks/s, **deliberately slower than the
Mother**). After `dummy-flee-seconds` (3s) of sprinting they **run out of stamina and pant in place for
`dummy-tired-seconds` (2s)** — that is the window where the Mother can actually land hits. They otherwise
wander nearby, jump over a one-block step **only when on the ground**, and if they end up hopelessly stuck they are moved to a standable spot (dummies only — never a
player or the Mother). They are **not invulnerable** (invulnerable entities never receive damage events);
the listener cancels the damage instead, so hits still produce knockback, red-cross particles and a hurt
sound, and the name tag shows the remaining hits. `dummy-hits` (2) downs one and a new one spawns 1 s later.

## 15. Before the first match (arena selection)

GHG does not generate a map; you mark an **arena** first. Data lives in `plugins/GHG/areas.yml` and

When you change the config structure, do all three at once: bump `ConfigManager.CURRENT_CONFIG_VERSION`,
add a CHANGELOG entry, and update the keys in `resources/config.yml`. The current version is **31**
(key **`ghg-config-version`**, GHG's own counter, unrelated to Gost's versioning, starting at 1).

Mismatched versions migrate automatically: the old `config.yml` is backed up to
`config_old_v<old>.yml`, the new template is written, then **every old key is written back** — losing a
hand-edited key is not acceptable. After that a small retune chain runs for keys that still hold the *old
default* (match length in v2, ticket prices in v5, self-heal in v6, altar cap in v7, Mother speed in v10,
and so on). Pure additions (queue in v15, spectate in v29) need no migration code.

The exception is **v9's config diet**: it uses the jar's `config.yml` as a whitelist and deletes Gost-era
dead keys (infection / demon hunter / ghost particles / `hunter.vault` …). To recover any deleted key, copy
it out of `config_old_v*.yml`.

## 17. State restore (inventory snapshots)

On join the plugin snapshots each player's **game mode / location / inventory + armour / health / food /
level and XP / flight state**. It restores all of it on leave, on match end, on disconnect, and on plugin
disable or crash recovery (a leftover snapshot is restored on next join). The selection tool is taken back
too, and anyone still in spectator mode with a stale snapshot is pulled out.

Rules enforced while a match is running: at most 9 items, items only in the hotbar, no stacking, no two
copies of the same non-shared item, and "Harvester"/"Divine Redemption" pinned to slot 0.

## 18. Match statistics

`plugins/GHG/stats.yml` keeps the last N matches plus totals: survivor wins, Mother wins, draws, average
length, and per-match charge seconds / downs / rescues / heals. `/ghga hunter stats [n]` prints them.
Test matches never enter the statistics, and draws are shown separately (a draw does not enter the win-rate
denominator).

## 19. Relationship with Gost

Gameplay and code provenance:

- **Gameplay**: inspired by **Dead by Daylight** (hunt / objectives / carry / rescue / endgame escape) and
  **Identity V** (altar sacrifice, wheelchair-style carry elimination, hatch)
- **Code**: **part of the source is taken from Gost** — the item framework (`ItemIds` /
  `ItemEffectRegistry`), area selection, localisation, the cross-version compatibility layer and the
  self-test all come from there, with the gameplay layer rewritten on top
- **Later**: a code audit is planned to remove whatever is no longer referenced. For the currently known
  leftovers see section 21

Three pieces of technical debt were paid off while adapting it:

1. **Item identity → stable IDs.** Items used to be identified by their Chinese display name, so renaming
   anything (or switching language) broke every listener. Now every custom item carries a stable ID in its
   `PersistentDataContainer` and the display name comes from the language files.
2. **Item effects → one registry.** Every "use an item" path (right click, chest loot, pick-up-and-use,
   debug commands) goes through `ItemEffectRegistry.use(...)`; cooldowns live there too. Items without a
   registered effect **do not cancel the vanilla action** (otherwise bread becomes uneatable).
3. **Match mode context → `MatchMode`.** A three-state `IDLE / CLASSIC / HUNTER` owned solely by
   `ModeManager`. Listeners check the mode first, otherwise the two rule sets fight. Entering a mode is
   pre-emptive: classic cannot start while GHG is running and vice versa.

Also fixed along the way: `ServerCompat.teleportSafely` now prefers `teleportAsync` (a synchronous
`teleport()` across regions throws on Folia), and `teleportPlayerToArea` uses it.

## 20. Engineering conventions

- **Six locales in sync**: every user-visible string lives in `resources/lang/*.yml` and all six files must
  share the same key set. Run `python tools/check_lang.py` after editing (key set + **leaf/parent
  conflicts** + line syntax + code key coverage)
- **A key may not be both a leaf and somebody's prefix**: Bukkit's `YamlConfiguration` treats `.` as a path
  separator, so `a.b` and `a.b.c` overwrite each other and `a.b` disappears at runtime (the log spams
  "missing language message"). Put child keys in a **sibling namespace**: `hunter.role.desc.icer`, not
  `hunter.role.icer.desc`
- **Old keys are never deleted**: historical language and config keys are kept; the config diet only
  removes Gost-era leftovers
- **Version bump**: see section 16
- **Pre-release check**: `/ghga selftest`
- **Build**: `gradle build` (Gradle 8.14 + JDK 17), output `build/libs/GHG_v<version>.jar`.
  On the dev machine the Gradle cache lives in `D:\MIMO\gradle-home` (`GRADLE_USER_HOME`) — do not write to C:
- Package name `io.Sriptirc_wp_1258.gost` matches upstream — **do not "normalise" it**, that would change
  `plugin.yml`'s `main` and every import

## 21. Known gaps

- **Multiple Mothers are not wired up**: `hunter.mother.ai-count` is readable (clamped 1–3) but spawning and
  behaviour (carry, camping, skill cooldowns, `MotherBrain`) still assume a single Mother
- **Mother pathing**: normal chases now use the Pathfinder toward a predicted point (`chase.*`) and fall back
  to vanilla targeting; with jump boost III, a 3 s stuck check and local escape she rarely locks up, but a
  **real maze can still make her loop** — pathing only sees the neighbourhood
- **Traces have one visibility level**: scratch and blood particles are **visible server-wide**; per-player
  visibility would need packet work (same limitation as the glowing effect)
- **No pallet/window play**: vault points were removed, so a chase is "run + items + role skill"
- **Item lore is not localised**: display names come from the language files, lore is still hardcoded Chinese
- **Draws do not enter the win-rate denominator**
- **Visual skills are global**: the Mother's passive sight uses `GLOWING`, which everybody sees, so survivors
  also see a teammate outlined
- **Clean-up plugins can remove the Mother**: a watchdog respawns her within 1 s, but the respawn position is
  near a survivor
- **The queue only starts matches, it does not switch maps**: the queue is empty after a match, you must
  `/ghg join` again. Spectating exists (`/ghg spectate`) but only while a match is running
- **The bundled config template still says version 1**, so a fresh install runs the whole v1→v31 migration
  chain and leaves a `config_old_v1.yml` behind. Values converge to the current defaults; it is just an extra
  backup file
- **Dead numbers in the startup table**: the "auto drop pool 4 kinds" counter is a leftover from the retired
  drop system (items only come from chests now)
